[5] 逆变换缩放约定核对 (用于排除 IFFT 缺缩放假设)
    原版 NsFft::Ifft (ns_fft.cc:54-61):
        WebRtc_rdft(kFftSize, -1, ...) 之后整体乘
        kScaling = 2.f / kFftSize = 0.0078125000
        Ooura rdft 对 half-complex 输入的逆变换输出 (N/2)*x[n],
        乘 2/N 后即标准 IDFT 时域序列 x[n]。
    ENC noise_suppressor.c:408 调用
        arm_rfft_fast_f32(&g_InstRfftF32, X, extended_frame, 1)
        CMSIS 路径 = merge_rfft_f32(压缩格式 -> 128 点复数)
                     + arm_cfft_f32(..., ifftFlag=1, ...)
        arm_cfft_f32 源码末尾执行  invL = 1.0f / L   (L = 128),
        官方文档: (The inverse transform includes a scale of 1/fftLen,
                   matches the textbook definition of the inverse FFT).
    手工推演 (两组边界输入):
      x[n] = 1         p = [256,0,0,...] -> pOut = [128+128j,0,...] -> 128 点逆变换含 1/128 -> 输出全 1
      x[n] = delta[n]  p 全 1 实部 -> pOut[k] = 1+0j 全通 -> 含 1/128 逆变换 -> 输出 delta
    两条路径最终都等于标准 IDFT, 输出同一时域序列
    => ENC 不存在 IFFT 缩放缺失问题。
    注意: merge_rfft 内部的 0.5 因子属于 (压缩格式 -> 复数格式) 的
          结构转换, 不是整体增益, 不能与 1/128 相乘后与原版 2/N
          直接比较 (0.5*1/128 = 0.00390625 与 2/256 = 0.00781250 不是同一层面的量)。

[6] 24bit 量纲下 Y[257] 污染的数值敏感性说明
    ENC 输入量纲: I2S_INOUT_RESOLUTION_LEVEL=2 -> (float)(i32 >> 8),
    即 ±8388608 (24bit)。256 点 FFT 的 DC 分量可达 256*8.4e6 ≈ 2.1e9,
    平方和可达 4.6e18, 仍在 float 范围内(上限 3.4e38)。
    因此 Y[257] 一旦取到栈上残留的大值, signal_energy 会被同量级放大,
    而不是溢出为 inf —— 表现为持续的、非随机的特征偏移。
